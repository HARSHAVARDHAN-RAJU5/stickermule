# Artwork Pre-flight Agent

An agent that inspects a customer's uploaded design against the product they
ordered, decides deterministically whether it can be printed, and routes the
job. Custom printing runs on artwork that arrives wrong in a small number of
predictable ways; catching those before a human proofs the file is worth doing
well.

**Deterministic checks decide. A language model only explains.** Every verdict
comes from a pure function over pixel measurements compared against a threshold
in a config file. No model output can change a verdict, add a finding, or
approve a file.

> Independent prototype. Not affiliated with, and not a description of, any
> printing company's internal systems. All test artwork is generated by the
> code in `tests/factories.py`.

## Run it

```
pip install -r requirements.txt
python -m preflight artwork.png --size 3x3 --shape die_cut
```

```
logo.png -> NEEDS_CUSTOMER_FIX  (214 ms)
  failing checks: ALPHA_FAKE
  [pass] RES_DPI        300 DPI at the ordered size
  [pass] ALPHA_MISSING  transparent background present (17.0% of pixels)
  [FAIL] ALPHA_FAKE     opaque region fills 100% of its bounding box and is a
                        uniform light colour; the background looks like a white
                        box, not a cut-out
```

`--json` prints the full findings. `--log runs/today.jsonl` writes the audit
trail. The exit code is 0 when approved, 1 otherwise, so it composes in a shell.

## Checks

Thresholds live in `config/thresholds.yaml`, never in the check bodies, so the
agent can be tightened without a deploy.

| Code | Measures | Fail | Warn |
|---|---|---|---|
| `RES_DPI` | `min(px_w / in_w, px_h / in_h)` | < 150 dpi | < 300 dpi |
| `ALPHA_MISSING` | transparent pixels, die-cut orders only | < 1% | — |
| `ALPHA_FAKE` | content filling its own bounding box, uniform and light | ≥ 97% | — |
| `SAFE_ZONE` | closest approach of content to the cut line | < 1/16 in | < 1/8 in |

Seven more are specified but not built: `ASPECT`, `BLEED`, `ALPHA_HALO`,
`STROKE_MIN`, `CONTRAST`, `CUT_RADIUS`, `FONT_EMBED`, `INK_LIMIT`.

## Routing

- any `FAIL` → `NEEDS_CUSTOMER_FIX`
- only `WARN`s, all in the auto-approvable set → `APPROVED` with notes
- any `WARN` outside that set, or a check that raised → `HUMAN_REVIEW`
- all `PASS` → `APPROVED`

The auto-approvable set is one list in `config/thresholds.yaml`. It is the
single lever an operations lead owns.

A check that raises becomes a `CHECK_ERROR` finding, which is deliberately not
auto-approvable: a broken check sends the job to a human instead of quietly
approving it.

## Known limits

- **No accuracy numbers yet.** The labelled 30-file evaluation set and its
  results table are the next thing to build. Until then this README claims
  nothing about how often the agent is right.
- **Raster only.** PDF and SVG uploads are refused with a clear message rather
  than half-handled.
- **Full-bleed designs defeat the background heuristic.** With no alpha
  channel, the background is found by flooding inward from the four corners. A
  design whose corners are all ink leaves nothing to flood, so no content is
  detected and the safe-zone check declines to report rather than inventing a
  measurement. Pinned by a test so it cannot regress into a silent pass.
- **The cut path is derived, not supplied.** For die-cut orders it is the
  content silhouette offset outward by 0.08 in, so safe-zone clearance is
  guaranteed by construction and the check is skipped. A customer-supplied die
  line would make it meaningful.
- **No colour management.** No ICC conversion, no press-accurate CMYK.
- **Thresholds are researched defaults**, not a production spec. A real printer
  would tune every one against their own equipment and remake data.

## Tests

```
python -m pytest tests -q
```

54 tests. Every fixture is generated rather than checked in, so the expected
findings are exact and the suite is reproducible from the repo.

## Layout

```
preflight/
  types.py       Canvas, ProductSpec, Finding, Verdict, State
  config.py      thresholds loaded from YAML
  eventlog.py    append-only JSONL audit trail
  normalize.py   01 - magic-byte sniffing, EXIF, RGBA
  analyze.py     02 - features every check shares
  checks/        03 - one pure function per check
  decide.py      04 - findings -> one of three routes
  pipeline.py    the state machine
config/thresholds.yaml
tests/
```
